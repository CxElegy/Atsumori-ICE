# 读取小红书岛建帖

这个项目（アイス島 改造プラン）一直靠小红书上的岛建帖找灵感。用户发来的通常是手机截图（`uploads/Screenshot_*_rednote.jpg`），偶尔是分享链接。这个 skill 负责把一篇帖子变成三类可用数据：

1. **帖子信息卡**：谁发的、梦境码、要点
2. **岛图网格**：全岛地图按 1 マス = 1 字符描进 `island-grid*.json`
3. **家具清单 / 模块**：把实景图里标注的家具转换成 `Module Builder.dc.html` 的模块

写进项目的文字一律用**日语**，和现有页面保持一致；跟用户对话用用户自己的语言。

## 0. 拿到内容

- **截图**：用 Read 直接看图。截图里能看到右上角的页码（如 `1/14`、`6/6`），说明帖子有多张图，截图只截到其中一张。需要其他页时，请用户补截图，不要猜没看到的页。
- **链接**（`xhslink.com/...`、`xiaohongshu.com/explore/...`）：可以用 WebFetch 试一次。小红书通常要求登录，也有反爬，拿不到正文时不要反复重试，直接请用户发截图。
- **别把截图里的界面当成内容**：日语界面上的「フォロー」「翻訳」「嫌い」「何か書いてみよう」是 App 自带的按钮，不属于帖子正文。

## 1. 判断图的类型

| 类型 | 特征 | 用法 |
|---|---|---|
| 全岛地图 | 俯视岛图，有 A–F 行、1–7 列的格线，有设施图标，常写着「梦境门牌号」 | → 第 3 步，描进网格 |
| 实景标注图 | 游戏内截图，白字标着家具名和数量（如「城墙×2」） | → 第 4 步，整理家具和模块 |
| 正文 / 攻略图 | 文字说明、步骤、配色、地形改造顺序 | → 帖子信息卡里的「ポイント」 |

一篇帖子里三类图可能都有，要分别处理。

## 2. 帖子信息卡

每篇帖子先整理出下面这张卡，用日语写，直接贴给用户或写进计划书的「参考」部分：

```
### 参考：<岛名或标题>
- 投稿者：<昵称>（小红书）／<日期> <地区>
- 夢番地：DA-XXXX-XXXX-XXXX（なければ「なし」）
- 反応：いいね <n> ／ 保存 <n> ／ コメント <n>
- タグ：#动森 #岛建 …（原文のまま）
- 画像：<見たページ>/<全ページ数>（未確認のページがあれば明記）
- 要点：
  - <この島・この作例から取り入れたいこと（例：川を細かく分けて斜めの道でつなぐ）>
  - <場所の条件（例：飛行場の入口を左に曲がった、入り江に面した小さな浜）>
- 原文の要約：<1〜3 行。中国語の固有名詞は原文を残す（例：海拉鲁岛、9¾站台）>
```

- 梦境码的格式是 `DA-` 加 3 组 4 位数字。截图里正文和地图下方各写一次的话，两处对一下，避免 OCR 读错。
- 保存数明显高于点赞数，说明这是一篇常被收藏的攻略帖，可以在要点里注明。
- 数字照截图原样写，不要四舍五入。

## 3. 全岛地图 → 网格

动森的岛图是 7 列 × 6 行的区块，每个区块 16×16 マス，整岛 **112 × 96 マス**。项目里的 `island-grid*.json` 就是这个尺寸：一个长度 96 的字符串数组，每个字符串长 112。

**字符图例**（和 `World Travel Island Plan v3.dc.html` 里 `draw()` 的色表 `C` 一致）：

| 字符 | 含义 | 字符 | 含义 |
|---|---|---|---|
| `S` | 海 | `t` | 树林 |
| `s` | 沙滩 | `p` | 道（土・石板） |
| `r` | 岩石 | `P` | 广场 |
| `w` | 河・池 | `K` | 砖块道 |
| `1` | 下段（第一层） | `b` | 桥 |
| `3` | 上段（崖上） | | |

步骤：

1. 用岛图上的 A–F / 1–7 格线定位，每个区块按 16×16 读取。截图被压缩时，先按格线把区块切开，逐块读。
2. **海岸线、岩石、飞机场、栈桥、河口、役場位置保持用户自己岛（アイス島）的不变**，只照抄参考岛的内陆部分（河、池、崖、道）。v2 / v3 就是这样做的：「海岸線・岩・飛行場・桟橋・役場は今のアイス島のまま。内側の川・池・崖・道は海拉鲁岛の配置を1マス単位で写しています」。
3. 设施图标（役場、飞机场、博物馆＝猫头鹰、商店＝狸猫、裁缝店、露营地、住民房）不写进网格，另外记下所在区块（例：`役場 E3`、`博物館 A3`），方便标在计划书的地图上。
4. 新网格存成新文件（`island-grid-<版本>.json`），不覆盖已有的文件。然后检查尺寸：

   ```bash
   python3 -c "import json,sys;g=json.load(open(sys.argv[1]));assert len(g)==96 and all(len(r)==112 for r in g),'size';print(sorted(set(''.join(g))))" island-grid-vN.json
   ```

   输出里只能出现上表中的字符。

5. 用户用 Happy Island Designer（eugeneration.github.io/HappyIslandDesigner）画了图并截图时，同样按 A–F / 1–7 格线读取，方法相同。

## 4. 实景标注图 → 家具清单和模块

### 4a. 家具清单

把图上每个标注读成一行，保留原文，加上日语名和数量：

```
| 原文 | 日本語 | 数 | 置き場所メモ |
|---|---|---|---|
| 城墙 | 城壁 | 2 | 奥の浜沿い |
| 城门 | 城門 | 3 | |
| 城塔 | 城塔 | 2 | 両端 |
| 旗子路灯 | 旗付きの街灯 | 1 | |
| 广场火车 | 広場の汽車 | 1 | 手前の砂浜 |
| 服务餐车 | ワゴン（サービスカート） | 1 | |
| 书堆 | 本の山 | 1 | |
| 电话亭 | 電話ボックス | 1 | |
| 公园时钟 | 公園の時計 | 1 | |
```

- 一个帖子有多张标注图时，同一件家具会重复出现。数量以**同一张图**里的标注为准，不同图之间不要相加，除非能确定拍的是不同位置。
- 标注里出现角色名（如「陌陌的包包」）时，那是指某个住民的家具，照原文记下，日语名后面括号注明「住民家具」。
- 认不出的标注照原文保留，日本語一栏写「？」，不要编造。

### 4b. 中文名 → Module Builder 图例

`Module Builder.dc.html` 的模块用字符串数组描述，每个字符是一マス，图例见文件里的 `LEG`。常见对照：

| 中文标注 | 字符 | LEG 名 |
|---|---|---|
| 城墙 | `W` | 城壁 |
| 城门 | `A` | 城門 |
| 城塔 | `Q` | 城塔 |
| 路灯、旗子路灯、半弧形路灯 | `L` | 街灯 |
| 电话亭 | `T` | 電話ボックス |
| 长椅、花园长椅 | `b` | ベンチ |
| 公园时钟 | `K` | 公園の時計 |
| 火车、广场火车、服务餐车、推车 | `C` | 汽車・カート |
| 木桶、木箱、书堆 | `x` | 樽・木箱 |
| 摊位、柜台 | `Y` | 屋台・カウンター |
| 地毯 | `R` | 絨毯 |
| 椰子树 | `P` | ヤシの木 |
| 栅栏 | `f` | 柵 |
| 鸟居 | `G` | 鳥居 |
| 石灯笼 | `n` | 灯籠 |
| 桌子 / 椅子 | `c` / `h` | テーブル / 椅子 |
| 遮阳伞 | `u` | パラソル |
| 篝火 | `X` | 焚き火 |
| 南瓜 | `k` | かぼちゃ |

| 风车 | `M` | 風車 |

没有对应字符的家具（如胡桃夹子娃娃、蜡烛、手摇风琴、牢笼）是装饰性小物件，不进网格，只写进模块的 `note`。

### 4c. 写成模块

以现有的 `lon_934`（9¾番線，就是从小红书「极致利用沙滩！我在动森造了个『9¾站台』」还原的）为范本：

```js
{ id: 'lon_934', th: 'ロンドン', name: '9¾番線（参考写真の再現）',
  r: ['QWWAWAWAWQ', 'BBBYBBBBLB', 'bBBCCCBBxB', 'bBBBBBBBBB', 'LBBBBBBBTB'],
  note: '城壁・城門×3・城塔×2を奥に、旗付き街灯、本の山とワゴン、汽車、樽、ベンチ、電話ボックス。浜の上に置く' },
```

- `id`：`<地区前缀>_<简称>`，地区前缀沿用现有的 `lon` / `egy` / `jpn` / `usa` 等。
- `th`：地区名（ロンドン、エジプト、日本、アメリカ…）。
- `name`：照着帖子还原的，在名字后加「（参考写真の再現）」。
- `r`：从照片的俯视角估算排布，**最后一行是靠近镜头的一侧**；`.` 表示空地。每行长度必须一致。
- `note`：用日语写清家具和数量、照片里放在哪里（「浜の上に置く」「飛行場の左」），以及没进网格的小物件。
- 加到 `MODS = this.genAll([...])` 里对应地区那几行的位置。照片里看不出的部分不要补全，在 note 里写「写真で見えない部分は省略」。

## 5. 收尾

- 帖子是灵感来源时，在用到它的计划书或模块的「参考にしたページ」里加一条，写清标题和作者；有梦境码时一并写上，方便用户去梦境参观。
- 把整理结果告诉用户：读到了哪几页、哪些页没看到、梦境码是多少、生成或修改了哪些文件。
- 别把截图里其他用户的头像、昵称以外的个人信息写进项目。
